## 2. 기술적으로 설명할 수 있는 내용
- 사용한 핵심 기술 및 선택 이유:
1) Python: 서비스의 화면 및 데이터 처리 로직을 구현하기 위해 사용
2) Streamlit: Python 코드로 웹 UI를 구성하고 평가 결과와 통계 데이터를 사용자에게 보여주기 위해 사용
3) Pandas: DB에서 조회한 데이터를 DataFrame으로 변환하고 표 및 통계 차트에 활용
4) PostgreSQL: 사용자 정보와 연습 기록 등 서비스 데이터를 저장하고 조회하는 데 활용
5) STT·평가 모듈 연동: 음성 인식 및 평가 결과를 UI에 연결해 사용자가 전사 결과와 발음 오류를 확인할 수 있도록 구성
- 가장 어려웠던 문제와 원인:
1) DB 조회 결과와 통계 화면의 표시 결과가 일치하도록 데이터 처리와 UI 연결을 함께 확인하는 과정 / sql이해 미숙
- 직접 구현한 해결 과정: 
1) Pandas DataFrame을 활용해 조회 데이터를 표와 차트에 사용할 수 있도록 가공
2) 기존 코드 전체를 변경하기보다 필요한 부분을 중심으로 수정하고, 화면에서 결과를 확인하는 방식으로 문제를 해결
- STT/TTS 파이프라인 이해 내용:
1) TTS는 연습 문장을 음성으로 변환해 사용자가 표준 발음을 듣고 따라 할 수 있도록 하는 과정
2) STT는 사용자가 녹음한 음성을 텍스트로 변환하는 과정
3) 발음 평가 과정에서는 정답 문장과 STT 전사 결과를 비교해 WER/CER 등의 지표와 오류 정보를 산출할 수 있음
4) UI 담당자는 이러한 처리 결과가 화면에 올바르게 전달되고 사용자가 이해하기 쉬운 형태로 표시되는지 확인하는 것이 중요

## 3. 협업·코드 리뷰
- 본인이 리뷰한 코드: app/ 파일의 streamlit 함수로  ui 구조 작업 및 src/, sql/ 연결
- 다른 팀원으로부터 받은 피드백: UI 구조 및 가독성, 데이터 연결 등에 대한 피드백을 받았음 
- 역할 분담의 적절성: 
1) STT 및 평가 알고리즘과 UI 구현을 분리하면 각 기능을 독립적으로 개발하고 테스트할 수 있다는 장점이 있었다.
2) UI 담당자로서 다른 팀원이 구현한 기능의 결과를 화면에 연결하는 통합 작업과 DB작업자와의 협업이 매우 중요했다.
