## 2. 기술적으로 설명할 수 있는 내용
- 사용한 핵심 기술 및 선택 이유: [ 
  - Python으로 전처리와 명령 처리 로직을 작성하고, Streamlit으로 녹음·텍스트 입력과 관리 화면을 구성함
  - faster-whisper는 한국어 음성을 텍스트로 변환하는 데 사용
  - TF-IDF와 분류 모델로 문장의 의도를 예측하고, 규칙 기반 슬롯 추출로 제목·내용·날짜 등 실행 정보를 구함
  - PostgreSQL과 Neon은 기록을 지속적으로 저장하고 여러 화면에서 같은 데이터를 조회하기 위해 사용했으며, edge-tts는 처리 결과를 음성으로 안내하는 데 사용함 ]
- 가장 어려웠던 문제와 원인: [ 개별 기능을 실행하는 것보다 입력부터 화면과 DB까지 결과를 일치시키는 과정이 어려웠다 초기 UI의 예시 데이터 및 세션 상태와 실제 DB 데이터가 섞여 화면 결과와 저장 결과를 따로 확인해야 했다<br> 같은 제목이나 키워드가 여러 일정에 존재할 때는 대상 구분이 어려웠고, 제목 포함 여부로 화면 상태를 변경하면 여러 일정이 함께 바뀔 수 있었다<br> DB에서 가져온 시간대 정보가 있는 날짜와 로컬에서 생성한 시간대 정보가 없는 날짜를 함께 정렬하면서 오류도 발생했다 ]
- 직접 구현한 해결 과정: [ 
  - 개인 브랜치에서 SQL, DB 함수, 전처리 및 화면 코드를 수정하고 실행 결과를 확인
  - 오류가 발생하면 입력 문장, 예상 결과, 실제 결과를 기록하여 팀원과 공유
  - Neon 연결과 테이블 존재 여부를 확인하고, 처리 이력과 실제 저장 데이터를 비교
  - 날짜 정렬 오류는 시간대 형식을 통일하는 방향으로 수정
  - 중복 일정 문제는 화면에서 제목으로 일괄 변경하는 부분과 DB의 대상 선택 로직을 나누어 검토하고, ID 기준 처리 및 대상이 여러 개일 때 추가 확인이 필요하다는 개선 방향을 공유 ]
- STT/TTS 파이프라인 이해 내용: [ 음성 입력은 파일 형식과 크기 등을 검사하고 모노 변환, 리샘플링, 무음 정리 등의 전처리를 거친 후 STT가 음성을 텍스트로 변환하고 사용자가 문장을 확인·수정한다 의도 분류와 슬롯 추출 결과에 따라 DB 작업을 수행하며, 실행 결과를 화면과 처리 이력에 표시하고 TTS로 읽어 준다 텍스트 입력은 STT 단계를 생략한다 의도 분류가 맞더라도 날짜나 대상 추출이 잘못되면 실제 명령 실행은 실패할 수 있으므로 단계별 검증이 필요하다 ]

## 3. 협업·코드 리뷰
- 본인이 리뷰한 코드: [ 전처리의 입력 검사·변환·중복 확인 코드, STT 입력 및 전사 결과 처리, 의도 분류와 슬롯 추출, 메모·할 일 CRUD SQL, DB 연결 함수, 홈과 관리 페이지의 상태 반영 코드를 실행 결과와 함께 검토했다. 특히 중복 제목의 처리 범위, 날짜 표현 인식, 삭제 대상 누락, 성공 상태와 실제 응답의 불일치 등을 확인하고 공유 ]
- 다른 팀원으로부터 받은 피드백: [ 
  - 팀원에게 최종 통합 코드를 기준으로 실행하고 Neon 연결 후 저장 결과를 확인하는 방법을 안내받음
  - 각자 구현한 코드의 함수명, 반환값, DB 컬럼과 사용 방식을 비교하면서 연동에 필요한 형식을 맞춤
  - 팀원이 공유한 명령 데이터, STT 코드와 TTS 테스트 결과를 참고하여 자신의 구현과 실행 결과를 비교함 ]
- 역할 분담의 적절성: [ 문서상 대표 역할은 일정과 산출물 취합에 도움이 되었다<br> 실제로는 5명 모두 처음부터 끝까지 기능을 구현해 보면서 전체 구조를 이해하고 서로의 결과를 비교했다<br>이를 통해 담당 영역 외의 기능도 학습할 수 있었다 다만 같은 파일을 각자 수정하면서 최신 버전과 적용 범위를 확인하는 데 시간이 들었다<br>다음에는 공동 구현 방식은 유지하되 최종 반영 담당자와 통합 시점, 함수·DB 규격을 먼저 정하면 혼선을 줄일 수 있다고 생각한다 ]
