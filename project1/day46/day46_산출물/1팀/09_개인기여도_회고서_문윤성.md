## 2. 기술적으로 설명할 수 있는 내용
- **사용한 핵심 기술과 선택 이유**:
  - **faster-whisper**: 한국어 음성 인식 정확도가 높고, 가벼운 서버 환경에서도 빠르게 문장을 뽑아낼 수 있어 사용했습니다.
  - **LinearSVC 모델**: 일상 대화처럼 짧고 조사가 생략된 음성 명령에서는, 일반 확률 모델보다 문장의 경계를 확실하게 갈라주는 LinearSVC가 정확도(97.2%)가 훨씬 높아 최종 모델로 선택했습니다.
  - **규칙 기반 보정**: AI 모델이 '도움말 보여줘'를 단순 조회로 착각하거나, '미완료'를 완료로 착각하는 실수를 막기 위해 중요한 키워드는 규칙으로 한 번 더 잡아주도록 구현했습니다.
  - **Neon PostgreSQL**: 브라우저를 껐다 켜거나 여러 사람이 동시에 접속해도 데이터가 날아가지 않고 안전하게 보관되도록 클라우드 DB를 연결했습니다.

- **가장 어려웠던 문제와 원인**:
  - 화면에서 일정을 지울 때 제목 글자만 단순 비교하다 보니, 날짜가 다른 '운동' 일정까지 한꺼번에 지워지는 버그가 있었습니다.
  - "내일 미완료 할 일 보여줘"라고 말했을 때, '완료'라는 글자만 보고 완료 처리로 넘어가서 '미'라는 할 일을 찾는 오류가 났습니다.
  - 처음에 Render 무료 서버에 배포했을 때 Whisper 모델 용량이 커서 메모리 부족(OOM)으로 서버가 다운되는 문제가 발생했습니다.

- **직접 해결한 과정**:
  - 화면에서도 DB의 고유 번호(ID)를 기준으로 1:1 매칭해서 지우도록 바꾸고, 지울 대상이 여러 개면 날짜를 되물어보도록 고쳤습니다.
  - '미완료' 단어는 완료 처리에서 제외하고, '보여줘/알려줘' 같은 조회 단어가 있으면 목록 조회가 먼저 실행되도록 순서를 바로잡았습니다.
  - 메모리 여유가 있는 Streamlit Community Cloud로 배포처를 바꾸고, 필요한 오디오 라이브러리 설정을 추가해 안정적으로 배포했습니다.

- **STT/TTS 파이프라인 이해 내용**:
  - 마이크 녹음 ➡ 16kHz 변환 ➡ Whisper 한국어 전사 ➡ 화면에서 문장 수정 ➡ 의도와 날짜 추출 ➡ DB 저장 ➡ 음성 답변 재생까지 이어지는 전체 단계의 동작 방식과 각 구간별 걸리는 시간을 파악하고 최적화했습니다.
