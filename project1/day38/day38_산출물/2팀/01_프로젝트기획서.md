## 1. 배경 및 해결할 문제
- 대상 사용자: 한국어 문장을 읽고, 음성 인식 결과를 확인하며 반복 연습하려는 외국인 학습자.
- 현재 문제: 정답과 전사 사이에 어떤 어절이 빠지거나 달라졌는지 즉시 확인하기 어렵고, 동일 문장의 반복 시도 결과를 체계적으로 비교하기 어렵다.
- 서비스 가치: 정답 TTS, 녹음·업로드, 전사 비교, 오류 위치 안내, 이력 시각화를 한 흐름으로 제공한다.

## 2. 핵심 사용자 시나리오
1. 사용자가 난이도와 문장을 선택하고 정답 TTS를 들은 뒤, 동의 안내를 확인하여 직접 녹음하거나 WAV를 업로드한다.
2. 시스템이 WAV 형식·길이·무음 여부를 검사하고 내부 처리 형식으로 변환한 후 STT로 한국어 전사를 생성한다.
3. 평가 모듈이 정답과 전사에 동일한 정규화를 적용하여 WER/CER를 계산하고 대체·삭제·삽입 위치를 표시한다.
4. TTS가 정답 또는 전사 기반 재연습 안내를 재생한다. 예: “정말이 누락된 것으로 인식되었습니다. 정답을 듣고 다시 읽어 보세요.”
5. DB에 문장, 전사, 평가 지표, 오류, 모델·정규화 버전과 시간을 저장한다. 사용자는 동일 문장을 재연습하고 시도별 변화를 확인한다.

## 3. 목표 및 범위
- MVP 필수 기능: ① B01~B10. 문장 30개 이상, ② 정답 TTS, ③ 녹음 또는 WAV 업로드 경로, ④ STT, WER/CER, ⑤ 오류 위치, ⑥ 텍스트·음성 피드백, ⑦ DB 이력, ⑧ 추이, ⑨ 동일 문장 시도 비교.
- 선택 기능: 로그인, 기록도전, 쓰기 연습 
- 제외 범위: 발음 정확도 확정, 임상 판단, 치료 효과 주장, 음향 지표만으로 발음 등급 부여, 인증 없는 개인 이력의 비공개 보장, 기본 음성 원본 장기 보관
- 정량 목표 및 근거: ① 쉬움/보통/어려움 각 10개 이상, 합계 30개 이상. ② D1 초안,  ③ D2 확정. 길이·조사·받침·숫자 표현을 다양화한다.

## 4. 기술 스택 및 선정 이유
| 계층 | 기술 | 선정 이유 | 대안 |
|---|---|---|---|
| UI | Streamlit | Python 기반 문장 선택·오디오·차트를 빠르게 통합 | FastAPI+별도 웹 UI는 일정상 후순위 |
| STT |faster-whisper, 한국어 small 모델을 우선 검토 | 로컬 추론 기준선과 처리 시간 비교에 활용 | 장비에 따라 base 모델 또는 사용 승인된 STT API |
| AI 핵심 | Python Levenshtein DP, 필요 시 jiwer 교차 검증 | 편집거리·정렬 원리를 설명하고 검증 가능 | jiwer 단독 사용 시에도 수동 검증 필수 |
| TTS | edge-tts 한국어 음성 우선 검토, D4 확정 |정답·피드백 음성 생성과 지연 비교 | 사전 생성 음성 또는 승인된 대체 TTS; 동적 피드백 음성 대체도 검증 |
| DB 연결 |psycopg, python-dotenv 도입 예정 | 파라미터 바인딩과 환경변수 관리 | 팀 승인된 PostgreSQL 드라이버 |
| DB | PostgreSQL | 문장·시도·오류 관계 및 이력 조회 | SQLite는 비상 로컬 데모용, 변경 시 범위 기록 |
| 배포 |초기 로컬, D6 배포 가능성 결정 | 모델 자원·속도·마이크 환경 확인 필요 | 로컬 시연 |
